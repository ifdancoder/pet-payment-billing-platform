# 3. Основа Kubernetes: среда выполнения, манифесты и проверки состояния

*[English version](0003-kubernetes-foundation.md)*

## Статус

Accepted

## Контекст

Всем сервисам нужны одинаковая среда выполнения, правила проверки состояния,
структура манифестов и граница секретов. Фоновые процессы должны запускаться
независимо, даже если используют один образ с API.

## Решение

### Среда выполнения и образы

Каждый сервис собирается на `dunglas/frankenphp:1-php8.5-alpine` и запускает
FrankenPHP в classic mode. Octane не установлен, поэтому состояние приложения не
сохраняется между запросами. Бинарник Composer копируется в базовый PHP-образ
для установки зависимостей; обязательные расширения, включая `sockets`, совпадают при
установке и выполнении.

Контейнеры работают с uid 1000. Каталоги записи Laravel и FrankenPHP принадлежат
этому пользователю. Один образ может запускать несколько процессов с разными
командами, например API Deployment, consumer Deployment и outbox
Deployment.

### Проверки состояния

| Endpoint | Проверка | Kubernetes probe |
| --- | --- | --- |
| `/health/startup` | HTTP-процесс отвечает | startup |
| `/health/live` | HTTP-процесс отвечает | liveness |
| `/health/ready` | доступно соединение PostgreSQL | readiness |

Liveness не зависит от PostgreSQL. При сбое базы readiness исключает поды из
Service без цикла перезапусков.

### Манифесты и секреты

Манифесты приложений используют Kustomize. Общая сторонняя инфраструктура может
подключать Helm-чарты через интеграцию Kustomize. Для каждого окружения создаётся
один namespace; сервисы разделяются метками и
ServiceAccounts.

Значения Secret не хранятся в Git. Локальные секреты создаются в игнорируемом
`.env` и применяются командой `make kind-secrets`. Shared environments должны
создавать Secret objects с теми же именами через External Secrets или аналогичный
operator.

## Последствия

API и фоновые процессы независимо масштабируются и перезапускаются, используя
общие образы. Переход на постоянные PHP workers требует аудита состояния
приложения. Число реплик, теги образов и ресурсы задаются в overlays окружений.
Компоненты на основе операторов остаются опциональными и требуют установки
контроллеров.
